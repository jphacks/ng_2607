# Re:Al Love Simulator

AT Protocol のアカウント認証と、ChatGPT（OpenAI API）を使う恋愛シミュレーションです。会話本文はBluesky DMに送受信し、キャラクター設定と好感度などのゲーム進行はこのPCのSQLiteに保存します。キャラの表示名とアイコンはAT Protocolの公開プロフィールから取得します。

プロフィール画面は「紹介・ふたりのヒミツ・思い出」のタブで表示します。プレイヤー向けの紹介文は、AI用の詳細設定と分けて管理画面で編集できます。設定項目と更新後の取り込み方法は [公開プロフィールの編集](PROFILE_UI.md)、演出の試し方は [UIプレビュー](UI_PREVIEW.md) を参照してください。

## 初回セットアップ

Python 3.10 以上、**Node.js 22.19 以上**、OpenAI の API キーが必要です。プロジェクトのディレクトリで実行します。`node -v` でバージョンを確認してください。Node.js 20 では現行の AT Protocol OAuth SDK が起動できません。

```sh
./scripts/setup.sh
npm install
```

`setup.sh` は `.venv` に Python の仮想環境を作ります。このプロジェクトに追加の Python パッケージはありません。OAuth 用の Node.js パッケージは仮想環境とは別に `npm install` で `node_modules` に入ります。`.venv` と `node_modules` は Git 管理対象外です。続けて下の「AI の設定（OpenAI API）」で `.env` に API キーとモデルを書きます。

## 普段の起動

アプリはプロジェクトのディレクトリで次のコマンドから起動します。`run.sh` が `.venv` の Python を使うので、仮想環境を手動で有効化する必要はありません。

```sh
./scripts/run.sh
```

ブラウザで `http://127.0.0.1:8765` を開きます。OAuth のループバックコールバックもこのアドレスを使うので、`localhost` の代わりに **127.0.0.1** で開いてください。停止するときは起動したターミナルで `Ctrl+C` を押します。

手動で起動する場合は `source .venv/bin/activate` の後に `python server.py` でも同じです。

実アカウントでの OAuth/DM 通信は、各アカウントの承認が必要なため自動テストでは確認していません。

## 使い方

1. `/` を開くと、未認証時はログイン画面へ進みます。自分のハンドルを入力し、「Blueskyでログイン」を押します。プレイヤーにはDM会話の取得・作成、本文の読み取り、送信権限を要求します。
2. `/characters` でキャラ用 AT Protocol アカウントのハンドルと長文プロフィールを保存します。表示名・アイコン・DIDは公開プロフィールから取得します。表示名がないアカウントではハンドルを名前として使います。
3. 「公開プロフィールを確認」で表示名とアイコンをプレビューできます。「保存してOAuth認証へ」を押すと編集内容を保存し、**キャラ用アカウント**の認証画面へ進みます。DMの会話一覧・本文の読み取りとAI返信の送信権限を要求します。アプリにパスワードを入力する欄はありません。
4. 管理画面でキャラの公開プロフィール・投稿・返信、DM会話一覧と本文を確認できます。投稿・DMはページ送りで最後まで閲覧できます。DM本文は原文を表示し、添付を含む取得データも展開できます。
5. ユーザー画面ではOAuth接続済みのキャラクターを選び、Bluesky DMで会話します。プレイヤーの発言はプレイヤーアカウントから、AIの返答はキャラ用アカウントから送信されます。初回の送信時に1対1会話を作成します。DM本文は表示時にAT Protocolから取得し、20秒ごとに新着を確認します。新しい会話本文はローカルDBに保存しません。好感度などの進行はPC内に保存されます。10往復で物語が終わり、リセットして新しい物語を始められますが、DM履歴はBluesky側に残ります。

ユーザー画面（「ひより」デザイン）は `static/index.html`・`static/login.html` と `static/hiyori-*` です。元のUIモックアップからの移行は完了しており、モック本体はリポジトリに含みません。

「ふたりだけのヒミツ」は、キャラごとに好感度25・50・75・100の4段階まで `/characters` で題名と本文を設定できます。本文が空欄の段階はありません。好感度が達するとプロフィールで公開され、一度公開されたヒミツは好感度が下がっても公開されたままです。公開の判定には下の総合好感度を使います。新しい物語は総合値18から始まります。未公開のヒミツの本文はプレイヤー画面に送りません。

## AI の設定（OpenAI API）

会話・好感度の判定・自動投稿・DM の自動返信のすべてで ChatGPT（OpenAI API）を使います。`.env` に OpenAI の API キーとモデルを書いてください。キーがないと AI を使う操作はエラーになります。

```sh
cp .env.example .env
chmod 600 .env                       # 自分だけが読めるようにする
# .env を開いて OPENAI_API_KEY= にキーを貼り付ける
.venv/bin/python scripts/check_ai.py # キーの確認と、使えるモデルの一覧
# 一覧から選んだモデルを .env の AI_MODEL= に書き、もう一度 check_ai.py で確認
./scripts/run.sh                     # 起動し直すと反映
```

`.env` は Git の管理対象外です。プレイヤーの発言・Bluesky の DM 本文・キャラ設定は OpenAI に送られます。料金は OpenAI の従量課金です。OpenAI 互換の API やプロキシを使うときは `OPENAI_BASE_URL` を書きます。

## Bluesky 自動運用（旧 bluesky_bot を統合）

`/characters` でOAuth接続したキャラには「Bluesky 自動運用」パネルが表示され、接続した本人のブラウザだけが編集できます。サーバーのバックグラウンドで次を行います（旧 `bluesky_bot` のアプリパスワードや launchd は使いません）。

- **1日の予定**: 曜日ごとの骨組み（JSON）から、その日の具体的な予定と小さな出来事をAIが作ります。投稿とDMには「今していること・ここまでの出来事」が事実として渡されます。
- **自動投稿**: パネルの「投稿時刻」（既定 `12:30, 19:00, 22:00`）に毎日、その時間の予定・出来事に合った文を生成して投稿します。30分以上遅れた時刻は見送ります。パネルから手動投稿もでき、「投稿のプロンプト」で AI に渡す全文を部品ごとに確認できます。
- **Pinksky のストーリー**: 「ストーリーの時刻」（既定 `20:00`）に毎日、その日の出来事から写真の場面と一言を AI が考え、OpenAI で画像を生成して投稿します。Pinksky（現 Pinkleap）は `pinkleapStory` タグ付きの Bluesky 画像投稿をストーリーとして表示するので、その形で送ります。Bluesky のタイムラインにも普通の画像投稿として残ります。画像は人物の顔・文字・ロゴを写さない写真風にしています。パネルの「ストーリーを生成」で画像を確認してから手動で投稿もできます。`shared/base_images/<ハンドル>.png` にキャラのベース画像を置く（または `/characters` で選ぶ）と、その絵と同じ絵柄・見た目のイラストで描き、キャラ自身も写るようになります（詳しくは `shared/base_images/README.md`）。画像生成は OpenAI の従量課金です（モデルは `.env` の `IMAGE_MODEL`、既定 `gpt-image-2`）。
- **DMの自動返信**: `getLog` で5秒ごとに新着を確認し、空き時間なら相手の発言で終わっている1対1の承認済み会話に返信します。寝ている・忙しい時間に届いたものは空き時間になってから返信します。ReAl から送られたメッセージにはゲームが返信し、ReAl が返事を作っている間は自動返信が待ちます。それ以外（Bluesky アプリから届いたDM）には、ReAl でゲームを始めた人にも返信します。返信（自動返信・ReAl の会話とも）には、キャラと相手それぞれの最近の公開投稿を渡すので、「この前の投稿見たよ」のような話に合わせられます。
- **投稿をきっかけに自分からDM**: 管理画面の「自分からDMで話しかける」をONにし、話しかける条件を選べます。既定の「なかよし以上」では総合好感度50以上または恋人の相手が対象です。「指定ハッシュタグ付き投稿」では、これまでDMした相手のタグ付き投稿に好感度に関係なく反応します。タグは `#結城めもり` など、キャラごとに1つ設定できます。タグ指定時は承認済み・ミュートしていない1対1の既存会話だけを対象とし、直近3日以内の対象投稿から最新の1件を話題にします。「同じ相手への話しかけを24時間に1回までにする」は既定でONです。OFFにすると、別の対象投稿には24時間以内でも反応できます。「相手の返信を待っている間は、新しい話題のDMを送らない」も既定でONです。こちらをOFFにすると、キャラが最後にDMを送っていても別の対象投稿に反応できます。両方の設定に関係なく、空き時間だけ・同じ投稿には1回だけです。「今すぐ話しかける（テスト）」も保存済みの条件に従いますが、24時間と返信待ちの制限を無視して**実際にDMを送信**します。
- **DM の好感度と ReAl の解放**: 自動返信のたびに、相手の発言から好意・信頼・恋愛感情を更新します（ゲームと同じ判定と計算）。総合好感度が設定値（既定40、初期値18）に達すると、その相手に ReAl のこのキャラを解放し、キャラが DM で ReAl に誘います。解放前のキャラは、キャラ選択に「まだ解放されていません」と進み具合が表示され、会話もできません。好感度はキャラと相手ごとにひとつで、Bluesky のDMと ReAl のどちらで話しても同じ値が上がります（覚えていることや、同じ行動の繰り返しの判定も共通です）。設定と相手ごとの関係値は「Bluesky 自動運用」パネルにあります。解放の条件を外せば誰でも遊べます。
- 記録は今日の予定に残ります。DM本文はローカルに保存せず、相手・時刻・メッセージIDだけを記録します。

自動投稿・自動返信には、キャラ用アカウントの追加権限（`getLog`・`updateRead`・投稿の作成）が、ストーリーには画像のアップロード（`blob:image/*`）が必要です。以前に接続したキャラは「保存してOAuthを再接続」で認証し直してください。不足している権限はパネルに表示されます。

旧 `bluesky_bot` の設定（めもりのペルソナ・投稿の話題・予定の骨組み）は取り込み済みで、フォルダは削除しました。**旧ボットを別のPCで動かしている場合は、二重に投稿・返信しないよう launchd ジョブを止め、アプリパスワードを Bluesky の設定で取り消してください。**

## 好感度（好意・信頼・恋愛感情の3軸）

好感度は「好意・信頼・恋愛感情」の3軸で管理します（初期値 30・20・0）。プレイヤーが発言するたびに次の順で更新し、返信の前に関係が変わります。

1. AIが、最新の発言が各条件（「SNS投稿に触れる」「約束を守る」「脅す」など56件）にどれだけ当てはまるかを0〜1で判定し、根拠の引用と理由を出します。判定には直近のDM、覚えていること（約束・自己開示・出来事など）、キャラの最近のBluesky投稿を渡します。
2. 変化量はプログラムが計算します（AIに数値は決めさせません）。条件の重み×該当度の合計に、次の補正をかけます。
   - 同じ行動の繰り返し: 直近5回の発言で同じ条件に当てはまった回数に応じて ×1.0 → 0.5 → 0.2 → 0
   - 恋愛感情の上昇は、好意と信頼が低いうちは小さくなります（×(0.2＋0.8×好意/100×信頼/100)）。下がる方には補正をかけません
   - 1回の発言での変化は各軸 ±5 まで。約束・告白・脅しなどの重要な出来事がはっきりあったときだけ ±10 まで
3. 更新後の3軸と覚えていることを踏まえてキャラが返信します。

画面のメーターとヒミツの公開判定には総合値 0.4×好意＋0.3×信頼＋0.3×恋愛感情 を使い、3軸と前回の変化量・判定の内訳はプロフィールで確認できます。10往復目の結末は、好意70・信頼60・恋愛感情50 をすべて満たすと最良になります。キャラごとの性格に合わせて、`/characters` で条件の重みを上書きできます（例: 誠実なキャラは嘘の減点を大きくする）。条件の一覧と標準の重みも同じ画面にあります。

判定に使うモデルは `.env` の `RELATIONSHIP_MODEL` で返信用 (`AI_MODEL`) と分けられます。小さいモデルは条件の選び間違いが増えるので、判定の精度を上げたいときは判定だけ上位のモデルにします（返信は安いモデルのままにできます）。使えるモデルは `scripts/check_ai.py` の一覧で確認できます。

判定の記録（条件・該当度・根拠の引用（100文字まで）・計算結果）と覚えていることの要約は、検証できるようローカルDBに保存します。会話本文そのものは保存しません。好感度は Bluesky のDMと共通なので、「新しい物語を始める」でリセットされるのは往復数・結末・ヒミツの閲覧状態で、好感度はそのまま残ります。

テストはプロジェクトのディレクトリで次のコマンドから実行します。

```sh
.venv/bin/python -m unittest discover -s tests
node tests/test_characters_oauth.cjs
node tests/test_hiyori_service.cjs
node tests/test_hiyori_engine.cjs
```

キャラのハンドルを変更すると、そのキャラの OAuth 接続は解除されます。DM 全体を見る管理 API は、そのキャラを OAuth 接続したブラウザセッションだけが利用できます。プレイヤー画面は認証済み DID と一致する会話だけを読めるよう、サーバー側で検査します。以前の読み取り専用OAuth接続は、プレイヤーとキャラ用アカウントの両方で再認証してください。

OAuth の承認は通常、アカウントごとに最初の1回です。アクセストークンは SDK が必要に応じて更新し、セッション情報は `data/oauth_sessions.json` に保存します。権限を取り消した場合、セッションの有効期限が切れた場合、またはハンドルを変更した場合は再認証してください。DM本文はAT Protocolから取得し、新しい会話本文をローカルDBには保存しません。既存バージョンで保存済みのローカル会話は安全のため自動削除せず、画面にも表示しません。

## チームでキャラ設定を共有する

DB（`data/game.sqlite3`）とログイン情報（`data/oauth_sessions.json`）、API キー（`.env`）は Git に入れません。ログイン情報やブラウザのセッション、話した相手の情報が入っているためです。代わりに、**キャラ設定だけ**を SQL ファイル `shared/characters.sql` にして Git で共有します。

| 共有するもの（`shared/characters.sql`） | 各自の PC に残るもの |
|---|---|
| ハンドル・表示名・DID・アイコン URL | OAuth の接続（各自が自分の PC で認証） |
| プロフィール、ふたりだけのヒミツ | ブラウザのセッション、API キー |
| 好感度の重み | 好感度・ゲームの進み具合・判定の記録 |
| 自動運用の設定（追加の指示・投稿の話題・1日の骨組み・ReAl の解放条件） | 予定と投稿・返信の記録、自動返信・自動投稿の ON/OFF |

### 設定を変えた人（書き出す）

```sh
.venv/bin/python scripts/export_shared.py   # shared/characters.sql を書き出す
git diff shared/characters.sql              # 変更点を確認する
git add shared/characters.sql
git commit -m "キャラ設定を更新"
git push
```

### 受け取る人（取り込む）

```sh
git pull
.venv/bin/python scripts/import_shared.py   # 自分の DB に取り込む
```

- キャラは**ハンドルで照合**します。PC ごとにキャラの番号が違っても、何度取り込んでも重複しません。
- 取り込むと、ファイルにあるキャラのプロフィール・ヒミツ・設定は**ファイルの内容で上書き**されます。ファイルにないキャラは消えません。
- 自分の OAuth の接続、好感度や進み具合、自動返信・自動投稿の ON/OFF は**そのまま残ります**。新しく追加されたキャラは OFF・未接続なので、`/characters` で「保存してOAuth認証へ」を押して接続してください。
- 取り込む前の DB は `data/game.before-import.sqlite3` に自動で保存されます。戻したいときは、サーバーを止めてからこのファイルを `data/game.sqlite3` にコピーします。
- サーバーを起動したままでも取り込めます。

### 初めて参加する人

```sh
git clone https://github.com/dogofsunrising/ReAl-Love-Simulator.git
cd ReAl-Love-Simulator
./scripts/setup.sh && npm install
cp .env.example .env && chmod 600 .env       # 自分の OpenAI API キーとモデルを書く
.venv/bin/python scripts/check_ai.py         # AI の設定を確認
.venv/bin/python scripts/import_shared.py    # チームのキャラ設定を取り込む
./scripts/run.sh                             # http://127.0.0.1:8765 を開く
```

### 注意

- **同じキャラの自動返信・自動投稿を、2台以上の PC で同時に ON にしない**でください。それぞれの PC のサーバーが返信・投稿するので、二重になります。ON にするのは担当の1台だけにします（取り込みで ON になることはありません）。
- 2人が同時に設定を変えると、`shared/characters.sql` が Git でコンフリクトすることがあります。そのときは片方の変更を `/characters` で反映し直してから、もう一度 `export_shared.py` で書き出してコミットしてください。
- 取り込みはファイルの SQL を自分の DB で実行します。チーム外から受け取ったファイルは取り込まず、`git diff` で中身を確認してから取り込んでください。
- `data/` と `.env` は `.gitignore` で除外しています。`git add -f` などで無理に追加しないでください。

## 保存先と設定

- `shared/characters.sql`: Git で共有するキャラ設定（上の「チームでキャラ設定を共有する」）。
- `data/game.sqlite3`: キャラ設定、好感度（3軸）と判定の記録・覚えていること、送信状態とDM ID、OAuthとブラウザの紐付け、自動運用の設定と日ごとの予定・記録。旧バージョンの会話本文は自動削除しません。
- `data/oauth_sessions.json`: OAuth のアクセストークン、更新トークン、DPoP キー等。OS ユーザー以外は読めない権限で作成します。このファイルとDBを機密として扱ってください。
- ブラウザ: HTTP-only Cookie のランダムなセッション ID
- `.env`: OpenAI の API キー（`OPENAI_API_KEY`）、モデル（`AI_MODEL`、好感度の判定だけは `RELATIONSHIP_MODEL`）、接続先（`OPENAI_BASE_URL`、既定 `https://api.openai.com/v1`）。Git の管理対象外です。

アプリの HTTP サーバーは `127.0.0.1` のみで待ち受けます。AT Protocol の OAuth には公式の `@atproto/oauth-client-node` を使い、PKCE、PAR、DPoP、トークン更新を処理します。プレイヤーとキャラ用アカウントにはDMの `getConvoForMembers`、`getMessages`、`sendMessage` 権限を要求します。キャラ用アカウントには管理画面用の `listConvos` と `getConvoAvailability`、自動運用用の `getLog`・`updateRead`・`app.bsky.feed.post` の作成も要求します。公開プロフィールと投稿は公開 AppView API から取得します。

参考: [OAuth with Node](https://atproto.com/guides/oauth-cli-tutorial)、[OAuth権限](https://atproto.com/specs/permission)、[Bluesky APIの経路](https://github.com/bluesky-social/bsky-docs/blob/main/docs/advanced-guides/api-directory.mdx)
