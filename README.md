# SNS から始まる恋愛シミュレーター、"**ReAl Love**"

## 製品概要

**ReAl Love（Re:Al Love Simulator）** は、AI キャラクターが実際の SNS（Bluesky / Pinkleap）で日常を投稿し、ユーザーはその投稿をきっかけに DM で会話して距離を縮めていく恋愛シミュレーションゲームです。

---

## 背景（製品開発のきっかけ、課題等）

私たちが通う名古屋工業大学には、異性との出会いが少なく、恋愛経験があまりない学生が多くいます。そんな学生たちの悩みの一つが、**「恋愛はしたい。でも、異性と何を話せばいいのかわからない」** というものです。

では、どうすれば自然に異性と会話するきっかけを作れるのでしょうか？

そこで私たちが注目したのが、**SNS** です。恋愛には慣れていなくても、SNS で友達の投稿を見たり、ストーリーに反応したりすることには慣れている学生が多くいます。それなら、**普段使い慣れた SNS をきっかけに、自然な恋愛を体験できるのではないか？**

この発想から生まれたのが、私たちの開発した恋愛シミュレーター、**「ReAl Love」** です。このアプリでは、AI のキャラクター自身が SNS に日常を投稿し、ユーザーはその投稿をきっかけに会話を始め、少しずつ距離を縮めていきます。

### 課題

**ペルソナ**:
- 異性との出会いが少ない理系大学生
- 恋愛はしたいが、何を話せばいいかわからない人
- SNS の投稿を見たり反応したりすることには慣れている人

従来の AI チャットアプリには、次のような課題があると考えました。

1. **会話のきっかけがない** - 白紙のチャット画面から、自分で話題を考えなければならない
2. **相手の日常が見えない** - AI の性格や趣味は、会話して聞き出すしかない
3. **関係が深まる過程がない** - 最初から親しげで、距離が縮まっていく体験がない

## 製品説明（具体的な製品の説明）

この製品は、SNS を通じて様々な趣味を持った AI キャラクターと出会い、お互いの SNS 投稿に触れながら好感度を高め、付き合うことを目指す恋愛シミュレーションゲームです。Bluesky と Pinkleap という 2 種類の SNS に対応しています。

![[Pasted image 20261025143437.png]]

ReAl Love は次の流れで遊びます。

1. **SNS で出会う** - AI キャラクターが Bluesky に日常の投稿を、Pinkleap にストーリーを毎日投稿します。ユーザーはそれを見てキャラクターを知ります。
2. **DM で話す** - 気になった投稿をきっかけに、スマホの Bluesky アプリから DM を送ります。キャラクターは自分の予定が空いている時間に返信します。
3. **ReAl で深める** - 好感度が上がると、専用のゲーム画面「ReAl」が解放されます。好感度のメーター、「ふたりだけのヒミツ」、プロフィールを見ながら会話できます。
4. **告白する** - 好感度が十分に高まったら、自分の言葉で気持ちを伝えます。受け入れられると恋人になり、特別な演出が流れます。

## 特長

### 1. AI は、日常生活を SNS に投稿する

従来の AI チャットアプリでは、ユーザーとの会話を通じて AI の性格や考え方を知ることが一般的です。

一方、本製品では、AI キャラクターが Bluesky と Pinkleap にそれぞれアカウントを持ち、日々の出来事や感じたことを投稿します。これにより、ユーザーは **AI との会話だけでは知ることのできない趣味や価値観、日常の様子** を知ることができます。

また、SNS の投稿が会話のきっかけとなることで、**実際の人間関係のように、相手の日常を知りながら自然に距離を縮める体験** を実現します。

- **1 日の予定を AI が作る** - 曜日ごとの骨組み（起床・仕事・配信など）から、その日の具体的な予定と小さな出来事を AI が毎日作ります。
- **予定に合った投稿** - 決まった時刻（既定 12:30 / 19:00 / 22:00）に、そのときの予定と出来事に合った文を投稿します。まだ起きていない未来の出来事は、AI に渡しません。
- **Pinkleap のストーリー** - 毎日決まった時刻に、その日の出来事から場面と一言を AI が考え、画像を生成してストーリーとして投稿します。キャラクターのベース画像を参照して描くので、毎回同じ絵柄・同じ見た目で登場します。

### 2. AI は、ユーザーが投稿した内容を基に会話する

キャラクターは、DM の返信を作るときに **自分の最近の投稿** と **相手（ユーザー）の最近の公開投稿** の両方を読みます。「この前の投稿見たよ」「ハッカソンお疲れさま！」のように、SNS 上の出来事が自然に会話へつながります。

さらに、キャラクターから話しかけることもあります。

- **仲良くなった相手に自分から DM** - 好感度が「なかよし」以上の相手が投稿すると、それを話題にしてキャラクターから DM を送ります。
- **ハッシュタグでも反応** - 指定したハッシュタグ（例: `#結城めもり`）付きの投稿にも、好感度に関係なく反応できます。
- **送りすぎない** - 同じ相手には 24 時間に 1 回まで、返事を待っている間は送らない、予定が空いている時間だけ、といった制限があります。

### 3. 好感度に応じた段階的な会話

好感度は **好意・信頼・恋愛感情の 3 軸** で管理し、総合値に応じてキャラクターの振る舞いが 4 段階＋恋人で変わります。

| 段階 | 総合好感度 | 振る舞い |
| --- | --- | --- |
| 知り合い | 0〜24 | 敬語で、距離感を保つ。踏み込んだ個人的な話はしない |
| 友達 | 25〜49 | タメ口になり、自分から積極的に質問する |
| なかよし | 50〜74 | 愛称で呼ぶ。自分から DM で話しかけるようになる |
| 恋人手前 | 75〜100 | 告白を受け入れる可能性がある |
| 恋人 | 告白の成立後 | 恋人としての口調・距離感で話す |

各段階の「呼び方・口調・してよいこと・しないこと」は、キャラクターごとに管理画面で編集できます。段階が上がるたびに **「ふたりだけのヒミツ」**（好感度 25 / 50 / 75 / 100）が 1 つずつ公開され、キャラクターの意外な一面を知ることができます。

![[Pasted image 20261025145145.png]]

### 4. 自分の言葉で告白する

告白ボタンはありません。「恋人手前」の段階では、送ったメッセージごとに **告白判定の AI** が会話の流れを読み、それが告白かどうかを判断します。

- 冗談や「好きかも」程度の曖昧な言葉は、告白として扱いません。
- 告白なら、好感度と会話の流れから受け入れるかどうかを決めます。好感度が高いほど、唐突な告白でも受け入れます。
- 断られると、好感度が 20 下がります。
- 受け入れられると恋人になり、キャラクター自身の返事とともに一枚絵の演出が流れます。

## 注力したこと（こだわり等）

### 1. 本物の SNS 上で動く AI キャラクター

専用アプリの中だけで完結させず、AT Protocol の OAuth でキャラクター用の実アカウントに接続し、Bluesky の投稿・DM と Pinkleap のストーリーを実際に送受信しています。ユーザーはいつもの Bluesky アプリから、そのままキャラクターと話せます。

- **公式 SDK による OAuth** - パスワードを預からず、PKCE・PAR・DPoP に対応した `@atproto/oauth-client-node` で認証
- **Pinkleap のストーリー投稿** - `pinkleapStory` タグ付きの画像投稿として送信
- **DM の新着を 5 秒ごとに確認** - Bluesky の `getLog` で新着だけを取得

**実装**: [oauth_bridge.mjs](oauth_bridge.mjs)、[automation.py](automation.py)

### 2. AI に数値を決めさせない好感度システム

AI に「好感度を +3 して」と決めさせると、甘くなったり極端になったりします。そこで、AI には **57 個の条件** にどれだけ当てはまるかだけを判定させ、変化量はプログラムが計算します。

- **条件の判定** - 「SNS 投稿に具体的に触れる」「約束を守る」「キャラの趣味を馬鹿にする」などに当てはまる度合い（0〜1）と、根拠の引用を AI が出力
- **繰り返しの抑制** - 直近 5 回で同じ行動を繰り返すと、効果が 1.0 → 0.5 → 0.2 → 0 倍に減少
- **恋愛感情は信頼の後から** - 好意と信頼が低いうちは、恋愛感情が上がりにくい
- **1 回の変化に上限** - 各軸 ±5 まで。約束・告白・脅しなどの重要な出来事のときだけ ±10 まで

**実装**: [relationship.py#L30-L85](relationship.py#L30-L85)（条件）、[relationship.py#L224-L258](relationship.py#L224-L258)（計算）

### 3. 時間と予定に沿ったリアルな振る舞い

キャラクターには 1 日の予定があり、寝ている時間や仕事中に届いた DM には、空き時間になってから返信します。投稿やストーリーも、その時刻の予定と出来事に合った内容になります。AI にはその時点までの出来事だけを渡すので、未来の予定を先取りした投稿はしません。

**実装**: [automation.py#L339-L360](automation.py#L339-L360)（今の予定と出来事）

### 4. 絵柄のそろったストーリー画像

画像生成 AI に文章だけで指示すると、毎回顔や絵柄が変わってしまいます。そこで、キャラクターのベース画像を参照画像として渡し、見た目は参照画像に任せて、プロンプトには場面だけを書くようにしました。

**実装**: [automation.py#L455-L500](automation.py#L455-L500)、[server.py#L842](server.py#L842)

### 5. UX へのこだわり

- **好感度のアニメーション** - 返信のたびに 3 軸の変化と判定の内訳を表示
- **ヒミツの公開演出** - 段階が上がると、新しいヒミツがポップアップで公開される
- **告白成立の演出** - キャラクター自身の返事とともに、一枚絵と演出が流れる
- **管理画面** - AI に渡すプロンプトの全文、今日の予定、投稿と DM の記録、相手ごとの関係を確認・編集できる

## 独自技術・注力ポイント

### ハッカソンで開発した独自機能

#### 1. 3 軸の好感度と段階的な振る舞い

AI の判定とプログラムの計算を分けた、好感度システムです。

1. AI が、最新のメッセージが 57 個の条件にどれだけ当てはまるか（0〜1）を、直近の DM・覚えていること・双方の SNS 投稿を踏まえて判定
2. プログラムが、重み × 該当度に繰り返し補正と上限をかけて、3 軸の変化量を計算
3. 総合値（0.4 × 好意 + 0.3 × 信頼 + 0.3 × 恋愛感情）から段階を決め、その段階の振る舞いを返信の指示に入れる

```python
# 恋愛感情は、好意と信頼が育つまではゆっくり上がる（下がる方は補正しない）
gate = 0.2 + 0.8 * (scores["affection"] / 100) * (scores["trust"] / 100)
positive["romance"] *= gate
for axis in AXES:
    cap = MAJOR_CAP if major[axis] else TURN_CAP  # 通常 ±5、重要な出来事は ±10
    delta[axis] = round1(clip(positive[axis] + negative[axis], -cap, cap))
```

**実装**: [relationship.py](relationship.py)

#### 2. 文脈から読み取る告白判定

「恋人手前」の段階では、すべてのメッセージを告白判定の AI に渡します。AI は `{clear, accept, reason}` の JSON で、はっきりした告白かどうかと、受け入れるかどうかを返します。曖昧な場合は判定しません。断られた場合は好感度を 20 下げます。判定結果は送信前に保存するので、通信エラーで送り直しても結果は変わりません。

**実装**: [relationship.py#L372-L432](relationship.py#L372-L432)、[server.py#L968](server.py#L968)

#### 3. SNS の投稿をきっかけにした、キャラクターからの DM

相手の直近 3 日以内の投稿から、まだ話題にしていない最新の 1 件を選び、今の段階の口調で話しかけます。ハッシュタグの判定は、Bluesky のタグ情報（facets / tags）を優先し、文字列の部分一致では反応しないようにしています。

**実装**: [automation.py#L718](automation.py#L718)、[automation.py#L218](automation.py#L218)

#### 4. チームでのキャラクター設定の共有

キャラクター設定（プロフィール・ヒミツ・プロンプト・段階の振る舞い）を SQL ファイルに書き出して Git で共有します。OAuth の接続、相手ごとの好感度、自動運用の ON / OFF は各 PC に残すので、複数の PC で同じキャラクターが二重に投稿・返信することを防げます。

**実装**: [shared_settings.py](shared_settings.py)

## データベース構成

### SQLite（`data/game.sqlite3`）

各 PC のローカルに保存します。DM の本文は保存せず、Bluesky から取得します。

#### 主なテーブル

- **characters**: キャラクター設定（プロフィール、公開プロフィール、好感度の重み、段階の振る舞い）
- **character_secrets**: ふたりだけのヒミツ（好感度 25 / 50 / 75 / 100）
- **character_automation**: 自動運用の設定（投稿・ストーリーの時刻、プロンプト、話しかけの条件）
- **character_schedules**: 日ごとの予定と、投稿・ストーリー・DM の記録
- **dm_relationships**: 相手ごとの 3 軸の好感度、ReAl の解放、恋人の状態
- **dm_relationship_events**: 毎回の好感度判定の記録（条件・該当度・根拠の引用・計算結果）
- **dm_relationship_memories**: 覚えていること（約束・自己開示・大切な出来事）
- **dm_turns**: ReAl での会話の送信状態と告白の判定結果
- **dm_reach_outs**: キャラクターから話しかけた記録
- **character_games / secret_progress**: ゲームの進行とヒミツの既読

---

## セットアップ

Python 3.10 以上、Node.js 22.19 以上、OpenAI の API キーが必要です。

```sh
git clone https://github.com/jphacks/ng_2607.git
cd ng_2607
./scripts/setup.sh && npm install
cp .env.example .env && chmod 600 .env       # OpenAI の API キーとモデルを書く
.venv/bin/python scripts/check_ai.py         # AI の設定を確認
.venv/bin/python scripts/import_shared.py    # チームのキャラ設定を取り込む
./scripts/run.sh                             # http://127.0.0.1:8765 を開く
```

詳細なセットアップ手順と使い方は [README.md](README.md) を参照してください。
